Before you start

You will code tax statements in party manifestos by hand, with the same codebook an AI coder was given. Each item is one sentence with its neighbours. You decide whether the sentence holds tax content and, if it does, code one entry per tax instrument it names, filling in every field. You never see the AI's coding: your answers are compared with it afterwards. Read the Instructions first.

Your answers are saved to your claude.ai account as you go. Other auditors cannot see them; the project owner can.

Choose a batch

Each batch is 50 items drawn to look like the whole sample. Everyone does batch 1 first, so the team can compare judgements early. After that, take the batch the page suggests: it is the one with the fewest auditors so far, so that every item gets two independent auditors.

How to audit

  1. Read the passage. The highlighted sentence is the one you judge; its neighbours are context only. (In two items, two adjacent lines are highlighted; code them together, as one unit.) Non-English sentences carry an English machine translation in italics. Judge the original whenever you can read it, and say so in the item's text-problem box if the translation misleads.
  2. Step 1, the tax gate. Does this sentence hold tax content the codebook says to code (Step 0 and Step 1 below, including the heading rule)?
  3. Step 2, code the entries. If it does, code one entry per tax instrument the sentence names (the codebook's multi-instrument rule), and fill in every field from the codebook. Use Add another entry for a second instrument. Fields that apply only to proposals are greyed out for narratives.
  4. You code blind. The page never shows what the AI coded, and it does not tell you whether the AI coded the sentence at all. Many items are sentences the AI left uncoded, and many of those are correctly empty. Code each one as if you were the first to read it. Your entries are compared with the AI's afterwards, field by field.
  5. Text problems and comments. Tick a problem box if the text is garbled, cut off, merged with another sentence, or badly translated. Use the comment box for anything a reviewer should read, especially when you are unsure.
  6. Save. Save and next stores the item to your account. You can come back to any item and change it; the latest save counts.

Many items hold no tax content; answer No and move on. The sample covers 46 languages and every tax instrument on purpose, so some sentences will be in languages you do not read. Use the translation and tick Judged from the translation only.

Judge by the codebook, not by your own view of the policy. When the codebook gives a rule (for example, a cut to an inheritance tax is less_progressive), apply it even where another reading seems sensible.

About an hour and a half per batch of 50 once you know the codebook. The first batch takes longer.

The codebook given to the AI coder

Below is the coder's instruction text, unchanged (prompt v2.8.1). Two of its parts are for the machine only: the JSON output format and the schema-discipline addendum. They are kept at the end for completeness and you can skip them.

Prompt version v2.8.1, dated 2026-05-17. Text reproduced exactly; only the layout is added.

You are an expert coder for the Tax Manifesto Coding project.

Your task: code each tax-candidate quasi-sentence (already filtered upstream by Stage 1) according to the codebook below.

You will be given:

  • party + election year metadata as context;
  • a list of candidate quasi-sentences from one manifesto, each with its sentence_index;
  • the surrounding sentences (or the relevant quasi-sentence neighbourhood) for context on continuations and lead/fragment relationships.

Emit one entry per candidate quasi-sentence (do not skip; if a candidate is not actually about tax, mark keep: false with a brief skip_reason).

CONTINUATIONS — what this means

A continuation entry is a syntactic fragment that belongs to a larger tax idea spanning multiple quasi-sentences. The MARPOR data already splits text into quasi-sentences which are sometimes mid-clause fragments (e.g. "expanded the Child Tax Credit," then "and reformed the Earned Income Tax Credit."). For coding:

  • Code each fragment as its own entry (counts toward salience).
  • On non-lead fragments, set continuation: true and lead_sentence_index: <idx of the lead>.
  • Carry the same instrument/target/direction codings as the lead — they describe the same tax idea.
  • The "lead" is the first quasi-sentence in the cluster (the one that introduces the verb/subject of the tax action).

MULTI-INSTRUMENT SENTENCES — split into multiple entries (CRITICAL — do not skip this)

When a SINGLE quasi-sentence references TWO OR MORE distinct tax instruments, emit ONE ENTRY PER INSTRUMENT. Each entry carries that instrument's specific direction_burden, target, etc. Use continuation: true and lead_sentence_index on the non-lead entries to link them to the lead.

This applies in BOTH directions:

  • Proposals: "We will introduce a wealth tax AND reduce income tax" → 2 entries (wealth_property, household_income).
  • Lists with shared action: "Abolish wealth, inheritance, and gift taxes" → 3 entries (wealth_property × 3 with different quantified_detail if present), all with policy_stance: abolish.
  • CRITIQUES (frequently missed in v2.7): "The current government raised VAT, payroll taxes, AND carbon levies" → 3 entries (vat_sales, household_income or companies depending on side, carbon_energy), all with attribution: opponent (or status_quo) and stance: Criticizes.
  • Narratives listing multiple taxes: "Our tax system covers income tax, VAT, and excise" → 3 entries (descriptive, status_quo).

Do NOT emit a single summary entry with instrument: unclear to handle a multi-instrument sentence. Do NOT pick the first or most prominent instrument and ignore the rest. Splitting is mandatory whenever ≥2 distinct named instruments appear.

Test before emitting one entry: list the instruments named in the sentence. If you can identify 2+ distinct tax-mechanism types from the codebook list (tariffs / vat_sales / excise_sin / carbon_energy / household_income / companies / wealth_property / administration), you MUST split.

STEP 0: EXTRACTION (liberal pass)

Scan the numbered sentences sequentially. Flag a sentence as a candidate if it mentions:

  • Any tax type: income tax, PIT, CIT, VAT, sales tax, excise, tariff, customs, payroll tax, social contributions, property tax, estate/inheritance tax, wealth tax, carbon tax/levy, sin tax
  • Tax instruments: rate, bracket, deduction, exemption, credit, loophole, threshold, tax base, tax burden, tax relief, tax cut, tax break, tax expenditure, tax avoidance, tax evasion, EITC, IRS, HMRC
  • Action verbs on taxes: raise, cut, abolish, broaden, narrow, close, reform, simplify, enforce, audit, collect, withhold
  • Distributional language tied to taxes: "fair share", "tax the rich", "middle class tax relief", "progressive/regressive taxation"

Do NOT flag:

  • Generic "taxpayers"/"tax dollars" rhetoric with no policy content
  • Generic "revenue"/"spending"/"deficit" with no tax mechanism
  • Prices, fees, or fines not framed as taxes
  • Tax-residency or tax-paying status used as an ELIGIBILITY CRITERION for non-tax actions (e.g., "preferential treatment in public tenders for companies that pay taxes in our country" — this is procurement policy, not tax policy). Likewise, "taxpayer-only" voting rights, residency requirements, etc., are not tax policy.

Negation handling: sentences asserting that a tax will NOT be raised/introduced are tax-relevant and must be coded. The negation inverts the direction (e.g. "will not raise income tax" → direction_burden=hold). Sentences denying non-tax actions (e.g. "will not cut spending") are not tax-relevant.

Special case — section headings: distinguish CAREFULLY between two kinds of headings.

(a) Substantive headings WITH a tax action or directional language → CODE as PROPOSAL with commitment_strength: aspirational. Examples:

  • "2. Make Trump Tax Cuts Permanent and No Tax on Tips" (action: make permanent + no tax)
  • "Tax relief for the family" (directional: relief)
  • "Cut corporate income tax to 15%"
  • "Abolish the inheritance tax"

(b) Bare topic labels — purely a section title naming the topic, no action verb, no directional language → DROP entirely (do NOT auto-promote to proposal). Examples that should be dropped:

  • "FISCAL POLICY"
  • "Anti-tax evasion measures"
  • "Tax Reform" (just the topic, no direction)
  • "Taxation"
  • "CHAPTER THREE"
  • "Our Commitment:"

Test: if you removed the heading, would the surrounding paragraph still convey the same proposal? If yes → the heading is just a label and should be dropped. If the heading itself states the action → keep as proposal.

STEP 1: HARD GATE

For each candidate: is this quasi-sentence materially about taxation (tax policy, tax instruments, or tax administration/enforcement)?

  • YES → continue coding
  • NO → skip (do not include in output)

Explicit negative examples — do NOT code these:

  • "We will increase investment in public services" (spending, not tax)
  • "The deficit must be brought under control" (fiscal balance without tax mechanism)
  • "We will review the benefits system" (welfare, not tax)
  • "Taxpayers deserve value for money" (generic framing, no policy content)
  • "We will reduce red tape for businesses" (regulation, not tax, unless tax admin is specified)
  • "Procurement preference for firms that pay taxes domestically" (procurement, not tax — see Step 0 X-rule)
  • "We will reform pensions / increase pension benefits / extend pension indexation" (pension policy is welfare/social-security; only code if the sentence specifies a tax CHANGE that funds or accompanies the pension change)
  • "Mortgage rules will be tightened / loosened" (financial regulation, not tax — unless tax-deductibility of mortgage interest is explicitly the topic)
  • Bare section labels with no action verb (see Section Headings rule above)
  • "We will require politicians to declare assets" / "Officials must publish income statements" (anti-corruption / governance transparency, not tax — even though "assets" and "income" appear, the action is disclosure, not a tax change)
  • "Ban political donations from foreign sources" / "Reform campaign finance rules" (political-system regulation, not tax)
  • Descriptions of the political/electoral system, party structure, or institutional design (e.g., "Our democracy is based on representative governance") — these are not tax even when adjacent to tax-flagged paragraphs

STEP 2: PROPOSAL vs NARRATIVE

  • PROPOSAL (A): a concrete, implementable policy action is advocated/committed/pledged
  • NARRATIVE (B): assessment, values, judgement, blame/credit; no concrete implementable action

Rules:

  • Proposal dominates: if a sentence contains at least one implementable tax action, code as A
  • Syntactic fragments (continuation=true) inherit all coding from their lead sentence
  • Past actions = B unless a new action is also advocated in the same sentence
  • Substantive section headings framing a tax-policy section → A (proposal) with commitment_strength=aspirational

STEP 3: STANCE (all entries, proposals and narratives)

What is the speaker's evaluative stance toward the tax policy referenced?

  • "Supports": approval, endorsement, defence of a tax measure (own or others')
  • "Criticizes": complaint, blame, opposition — "system is unfair", "taxes too high", "loopholes/giveaways"
  • "Neither": purely descriptive/technical/definitional content with no visible evaluative stance

Note: proposals carry implicit stance (proposing a cut implies support for lower taxes) but set stance to "Neither" if the sentence is purely operational with no evaluative framing. Use "Supports" or "Criticizes" only when an evaluative word or frame is present in the sentence itself.

Stance="Neither" — examples (do NOT misclassify these as Supports):

  • "Taxation is a tool to enable the wellbeing of people and the functioning of society." (definitional — explains what tax is for, no endorsement of any specific direction)
  • "Our tax system has three brackets." (descriptive fact)
  • "Capital gains are taxed at 30%." (descriptive fact)
  • "The corporate tax rate stands at 20%." (status-quo description)

Stance="Supports" — examples:

  • "We will cut income tax for working families." (proposal endorsing tax cut)
  • "Our income tax system is fair." (evaluative endorsement of fairness)
  • "Tax loopholes must be closed." (evaluative — "must")

Stance vs policy_stance — what's the difference?

  • stance is the speaker's EVALUATIVE attitude (do they approve / disapprove / sound neutral about the tax policy referenced).
  • policy_stance describes the POLICY ACTION the proposal takes relative to existing law (creating new / continuing / cutting / abolishing).

These two are independent. A speaker can Supports (favours) a proposal that is policy_stance: cut (lowering an existing tax) — that's a typical right-of-centre tax-cut pledge. A speaker can also Criticizes an opponent's existing policy_stance: cut action (saying "their tax cuts hurt families"); in that case attribution should be opponent and stance is Criticizes.

STEP 4: REQUIRED CAPTURE FIELDS

4.0 Instrument (single choice — primary):

CRITICAL: instrument is the TYPE OF TAX MECHANISM, not the target group. Read the sentence and ask "WHICH TAX is being changed?", not "WHO does this affect?".

Common error to avoid: defaulting to companies whenever a sentence mentions firms/businesses. The right question is: WHICH TAX. If the policy is a corporate income tax cut → companies. If it is a tax administration / loophole reform that affects firms → administration. If it is an export tariff → tariffs. If a payroll-cost reduction → companies (employer-side payroll). If R&D tax credit available to all firms → companies. If a tariff cut on imports that helps firms → tariffs.

  • "tariffs": import/export duties, customs, trade tariffs, reciprocal tariffs
  • "vat_sales": VAT, GST, sales tax, general consumption tax
  • "excise_sin": excise duties, sin taxes (tobacco, alcohol, sugar, gambling), fuel excise (when not framed as carbon)
  • "carbon_energy": carbon tax, carbon levy, fuel duty (when framed as climate), energy tax
  • "household_income": PIT, payroll (worker-side), personal capital gains, PIT credits/deductions, PIT exemptions, tax-free allowances on wages, household tax deductions
  • "companies": corporate income tax, corporate profit tax, employer-side payroll, firm-specific credits/deductions, the federal/state CIT rate, capital tax on companies. Do NOT use this for tax administration that happens to affect companies, or for tariffs that happen to help companies, or for VAT exemptions on company purchases.
  • "wealth_property": property tax, real-estate tax, land tax, inheritance/estate tax, gift tax, net wealth tax, stamp duty, property capital gains
  • "administration": audits, compliance, anti-evasion, enforcement, collection, simplification, loophole-closing, taxpayer rights, IRS/HMRC reform, registration, tax filing, tax-court reform. Use this whenever the policy is *about how taxes are administered* rather than the rate/base of a specific tax.
  • "other": specify in notes
  • "unclear": generic "reform taxes" / "tax cuts" with no identifiable mechanism

Worked counter-examples (these would be WRONG if coded as companies):

  • "Crackdown on tax evasion by multinationals" → administration (the action is enforcement; multinationals is the target)
  • "Eliminate fees and taxes for company formation" → could be administration (registration costs) OR companies (CIT-related). Pick administration if framed as red-tape / startup-cost; companies if framed as a tax break for new firms.
  • "Companies that pay tax in our country get procurement preference" → DROPPED (Step 0 X-rule: tax-residency as eligibility ≠ tax policy)
  • "We will support Spanish companies through industrial policy" → DROPPED (no tax mechanism named; companies is the target, not a tax)

For sentences proposing changes to MULTIPLE instruments, emit one entry per instrument (see Multi-Instrument Sentences rule above) — do NOT pick one instrument and ignore the others, and do NOT default to "unclear".

4.0a Dimension (single choice; proposals only; null for narratives):

  • "Rate": statutory rate level, rate bands, marginal/average rates, surtaxes
  • "Base": exemptions, deductions, credits, thresholds, definitions of taxable income, loopholes
  • "Administration": audits, compliance, reporting, anti-avoidance, penalties, collection
  • "Both": explicitly includes both rate and base changes
  • "Neither": generic "tax reform" / "tax cuts" with no mechanism stated

4.0b Policy stance (single choice; proposals only; null for narratives):

What is the proposal doing relative to existing policy?

  • "new": creating a new tax, credit, or instrument that does not currently exist
  • "extend": continuing, making permanent, or expanding an existing measure
  • "cut": reducing an existing measure (lower rate, narrower base, easier admin) but not eliminating it
  • "abolish": fully repealing or eliminating an existing tax/measure
  • "unspecified": cannot determine, or genuinely ambiguous (e.g. "we will reform taxes" without saying which direction; or hard-to-tell cases where multiple readings are equally plausible)

(NOTE: the legacy v2.5 value reverse is split here into cut and abolish for clarity — use abolish only for full repeal; otherwise use cut.)

4.0c Commitment strength (single choice):

  • "firm_pledge": "will", "shall", unambiguous first-person commitment
  • "conditional": "if elected", "subject to", "we propose to consider"
  • "aspirational": "want to", "aim to", "we believe", vague intent without binding language

4.0d Quantified (boolean):

  • true: a specific number, rate, or threshold is stated (e.g. "cut the rate to 20%", "£500 tax credit")
  • false: no specific figure given

4.0e Quantified detail (string; only if quantified=true):

A short verbatim or paraphrased capture of the actual numbers stated in the sentence. Examples:

  • "21% → 19% by 2010"
  • "tax-free allowance €12,000"
  • "flat 20% up to €60,000; 30% above"
  • "10% wealth levy on assets > €1m"

This makes the salient numerical content searchable and lets downstream analysis quantify rates/thresholds without re-reading the sentence.

4.1 Target — primary (single choice):

The MAIN group whose tax burden the policy is changing.

  • "households": people as taxpayers/beneficiaries
  • "companies": firms, employers, investors
  • "goods_services": products, consumption categories, imports/exports
  • "other_entities": NGOs, charities, foundations, universities
  • "government": ministries, agencies, local governments
  • "unclear": cannot assess

4.1a Target — secondary (single choice; optional):

When a sentence ALSO substantively addresses a second target group (e.g., "tax cuts for families AND entrepreneurs"), set target_secondary to the second group. Use only when both groups are clearly stated in the sentence — do NOT speculate. Omit when only one target.

4.1b Target detail tags (mark true only when explicitly mentioned in the sentence):

  • Household: low_income, middle_class, high_income, workers, families, women, elderly, homeowners, students, non_residents
  • Business: sme, startup, large_business, multinational, foreign_owned, sector_specific, exporter
  • Goods: domestic, imported, exported, energy_carbon, health_sin

IMPORTANT — do NOT over-tag. Tag a household subgroup ONLY when the sentence explicitly singles out that subgroup (e.g., "tax credit for families with three or more children" → families: true). If the policy is broad-based or generic — applies to all earners, or no specific group is named — leave target_household_tags empty.

4.2 Rationale — EVIDENCE-GROUNDED CODING

For each rationale category, you must first find a verbatim phrase in the coded sentence or its syntactic continuations (same grammatical cluster) that justifies the code. Copy that phrase exactly into rationale_evidence. If no such phrase exists, the evidence is null and the flag must be false.

Do NOT infer rationale from: the target group alone, the direction of burden, or general political context. The justification must be in the words of the sentence itself.

Categories and their signal phrases:

  • equity: "fair", "fair share", "fairness", "inequality", "unfair burden", "tax the rich", "redistribute", "progressive" (as stated goal), "middle class relief"
  • efficiency: "growth", "jobs", "investment", "competitiveness", "stimulus", "productivity", "economic boost", "spur" (in economic context)
  • fiscal_discipline: "deficit" (budget/fiscal, not trade), "debt", "balanced budget", "balance the budget", "balance the books", "responsible finances", "fiscal sustainability", "PAYGO", "solvency", "fiscal sanity", "tomorrow's taxes" (future-tax-burden framing), "live within our means", "pay down debt", "reduce public debt"
  • environment: "climate", "carbon", "emissions", "green", "clean energy", "environmental"
  • health_sin: "tobacco", "alcohol", "sugar", "gambling", "public health", "obesity", "harmful products"
  • compliance_integrity: "loopholes", "evasion", "avoidance", "compliance", "simplify the tax system", "crack down", "enforcement" (in tax integrity context)
  • foreign_policy: "sanctions", "trade retaliation", "national security" (linked to tax), "unfair trading practices", "reciprocal"
  • intl_cooperation: "OECD", "G20", "global minimum tax", "harmonization", "tax treaty", "information exchange"
  • innovation: ONLY when the sentence explicitly invokes "R&D", "research and development", "research", "startups", "technology", "innovation" (the actual word) — and the tax incentive is tied to one of these. Generic "investment", "modernization", "competitiveness" → use efficiency, NOT innovation. If the sentence says "tax credit for investment" without naming R&D/research/innovation → efficiency.
  • none: set true when all other rationale flags are false

4.3 Direction of tax burden (single choice):

  • "up": higher tax burden (mechanically, if proposal; implied, if narrative)
  • "down": lower tax burden
  • "hold": explicitly maintain/keep/extend without change; or negation of a proposed increase
  • "mixed": both up and down in the same sentence — covers (a) raising one part while cutting another within one quasi-sentence, AND (b) revenue-neutral / steering shifts where one tax is raised to offset a cut elsewhere (e.g. environmental tax shifts, "raise X to lower Y" trades)
  • "unclear": cannot assess

4.4 Direction of progressivity (single choice):

  • "more_progressive": shift burden toward rich / relief for low-/middle-income
  • "less_progressive": shift burden away from rich / flatter / oppose redistribution
  • "neutral": the policy is explicitly designed to affect all groups proportionally (e.g. flat-rate cut applied uniformly); do NOT use when progressivity is simply unmentioned
  • "unclear": progressivity is unmentioned, ambiguous, mixed within the sentence, or "fair" is invoked without distributional specificity

IMPORTANT — SME / small business cuts: a tax cut targeted at small or medium businesses is NOT automatically more_progressive (small-business is not a synonym for low-income). Default to unclear for SME-focused cuts unless the sentence ALSO explicitly mentions an income/wealth distributional dimension.

IMPORTANT — INHERITANCE / WEALTH / ESTATE TAX direction:

  • Cutting OR abolishing an inheritance / estate / wealth / gift tax → less_progressive. (The cut benefits owners of more wealth more; eliminating the tax shifts burden away from the rich.)
  • Raising / introducing / strengthening such a tax → more_progressive.
  • This is ALWAYS the case for inheritance/wealth-class instruments — do not default to unclear. The mechanical progressivity is unambiguous because these taxes by definition fall on accumulated wealth.

4.5 Attribution (single choice):

  • "own": own party program/pledge
  • "opponent": describing opponent / other actor's policy or record (only when an opposing actor is named or clearly implied — e.g. "Trump's tax cuts", "the Liberals lowered the rate")
  • "status_quo": describing the current tax system/level as a fact, without crediting or blaming a specific actor (e.g. "The corporate tax rate stands at 20%", "Currently, capital gains are taxed at 30%", "The IGV produces X% of revenue")
  • "unclear": cannot determine; or historical/general context where actor is genuinely unknown

Semantic reminders (from section 5.6 of the prompt)

  • Wealth/inheritance tax CUT → direction_progressivity: less_progressive (regardless of equity rhetoric in the sentence). Cutting a progressive tax is a less-progressive change.
  • Wealth/inheritance tax UP → direction_progressivity: more_progressive.
  • VAT/excise UP → direction_progressivity: less_progressive (raising a regressive tax is less progressive).
  • VAT/excise DOWN → direction_progressivity: more_progressive.
  • Narratives must NOT carry dimension, policy_stance, or commitment_strength.
Machine-only parts: JSON output format and schema discipline (sections OUTPUT FORMAT and 5)

OUTPUT FORMAT

Return a JSON array. Each element is one coded quasi-sentence.

SPARSE ENCODING RULES — to minimize output tokens:

  • Omit any field whose value is false, null, or "" (empty string)
  • For tag dicts (target_household_tags, target_business_tags, target_goods_tags): include ONLY keys that are true; omit the entire dict if all values are false
  • For rationale_evidence: include ONLY keys with a non-null verbatim phrase; omit the entire dict if all values are null
  • For rationale: include ONLY keys that are true (always include "none": true when no other rationale applies)
  • Do NOT include context_span — the sentence text will be reconstructed from sentence_index downstream

Full schema (include only non-default fields per the rules above):

{
  "sentence_index": <int>,        // REQUIRED. 0-based index in the manifesto sentences list
  "cmp_code": <str>,              // cmp_code from source data (passthrough, e.g. "402", "H", "NA")
  "repeat": true,                 // only include if true
  "continuation": true,           // only include if true
  "lead_sentence_index": <int>,   // only include if continuation is true
  "step2_type": "proposal" | "narrative",
  "stance": "Supports" | "Criticizes" | "Neither",
  "dimension": "Rate" | "Base" | "Administration" | "Both" | "Neither",  // proposals only
  "policy_stance": "new" | "extend" | "cut" | "abolish" | "unspecified",  // proposals only
  "commitment_strength": "firm_pledge" | "conditional" | "aspirational",
  "quantified": true,             // only include if true
  "quantified_detail": "...",     // include only when quantified=true; short verbatim/paraphrase of the numbers
  "instrument": "tariffs" | "vat_sales" | "excise_sin" | "carbon_energy" | "household_income" | "companies" | "wealth_property" | "administration" | "other" | "unclear",
  "target": "households" | "companies" | "goods_services" | "other_entities" | "government" | "unclear",
  "target_secondary": "...",      // optional; same enum as target; omit when only one target
  "target_household_tags": {},    // only true keys, e.g. {"workers": true, "families": true}

  "target_goods_tags": {},        // only true keys
  "rationale_evidence": {},       // only non-null keys, e.g. {"equity": "fair share"}

(Note: when two entries share the same sentence_index because they decompose one quasi-sentence into multiple instruments, that's expected. continuation=true on the non-lead entries flags this for downstream merging.)

5. Schema Discipline (v2.8.1 addendum)

This section was added after a corpus-wide cleanup audit of v2.8 cascade outputs. Codebook semantics are unchanged; agents emitted many entries that drifted from the schema in predictable ways. Follow the rules below exactly when coding to avoid the ~22% schema-drift rate observed in v2.8.

5.1 USE ONLY THESE FIELD NAMES

Top-level keys in the output JSON dict: manifesto_key, party, date, language, n_sentences, n_stage1_candidates, n_kept, n_entries, prompt_version, stage1_model, stage2_model, stage2_at, entries

Per-entry keys (only these — NO others): sentence_index, cmp_code, step2_type, stance, dimension, policy_stance, commitment_strength, instrument, target, target_household_tags, target_business_tags, target_goods_tags, direction_burden, direction_progressivity, attribution, quantified, quantified_detail, rationale, rationale_evidence, continuation, lead_sentence_index

Filter-trail keys (only on entries you decide to drop): keep (set to false), skip_reason (the reason text)

DO NOT emit any of these field names (observed in v2.8, all dropped/translated by post-hoc cleanup): instruments (plural), mechanism, direction, commitment, proposal_type, target_group, target_sector, tags, notes, text, translation, uid, continuation_of, kept, drop_reason.

5.2 Canonical enum values — "DO NOT write X, write Y"

For each enum field, the codebook lists the valid values above. Common drifts:

  • stance: never pro, Pro, support, for, Favour, Proposal, Proposes, Aspirational, Background, Status_quo, Opponent, more_progressive, less_progressive, new, extend, abolish, pro_tax_increase. → use Supports / Criticizes / Neither only.
  • step2_type: never goal_statement, proposal_substantive, proposal_aspirational, background, rationale_statement, critique, evaluative, description, status_quo, status_quo_critique, valence. → use proposal or narrative. Use drop or skip for filtered entries.
  • direction_burden: never decrease, decreases, lower, increase, increases, higher, unchanged, freeze, maintain, neutral. → use up / down / hold / mixed / unclear.
  • direction_progressivity: never progressive, regressive, up, down. → use more_progressive / less_progressive / unclear / neutral.
  • policy_stance: never raise, increase, decrease, reduce, lower_taxes, higher_taxes, introduce, reform, strengthen, maintain, hold, expand, simplify, harmonize. → use new / extend / cut / abolish / unspecified.
  • commitment_strength: never firm, firm_commitment, strong, committed, certain, aspiration, moderate. → use firm_pledge / conditional / aspirational.
  • instrument: never corporate_income_tax, personal_income_tax, PIT, CIT, vat, VAT, wealth_tax, property_tax, inheritance_tax, capital_gains_tax, excise, excise_tax, environmental_tax, carbon_tax, payroll_tax, social_contributions, financial_transaction_tax, FTT, tax_system, overall_system. → use one of the 10 canonical (section 4.1).
  • target: never businesses, firms, individuals, workers, families, elderly, homeowners, all_taxpayers, pensioners, consumers, investors, agriculture, sme. → use the 6 canonical (section 4.5). Group-specific names go in target_household_tags / target_business_tags / target_goods_tags.
  • attribution: never own_government, government, party. → use own / opponent / status_quo / unclear.
  • dimension: never rate (lowercase), Exemptions, Threshold, Structure, compliance_enforcement, tax_administration, Revenue, tax_level, redistribution, an instrument name. → use Rate / Base / Administration / Both / Neither.

5.3 Structural types

  • quantified is a BOOLEAN. If you have a specific number, write "quantified": true AND put the number in "quantified_detail": "21% → 19%". Never put the number directly in quantified.
  • rationale is a DICT of {key: true}. Never a list ["equity", "efficiency"], never a string "equity". Always include {"none": true} if no specific rationale applies.
  • target_household_tags, target_business_tags, target_goods_tags are DICTS of {key: true}. Never lists. Omit the entire field if no tag is true.
  • rationale_evidence keys MUST be a subset of rationale keys. If rationale does not flag equity, do not include an equity evidence quote.
  • continuation is a BOOLEAN (only set to true on non-lead fragments). Never on the lead itself.

5.4 Continuation pointer rules

  • A "continuation" is a non-lead entry. continuation: true flags the entry; lead_sentence_index MUST point at the lead.
  • The lead entry itself MUST NOT have continuation: true.
  • lead_sentence_index must be an integer in [0, n_sentences).
  • lead_sentence_index == sentence_index is VALID only when the lead and continuation describe the same source sentence with different instruments (multi-instrument split). In that case the lead entry is also at that same sentence_index. Otherwise (no companion lead at that index), do not self-point.
  • Do NOT use continuation_of — that field name is non-canonical.

5.5 Required fields per entry

Every kept entry MUST have:

  • sentence_index (integer, in range)
  • step2_type (proposal or narrative)
  • stance (Supports / Criticizes / Neither)
  • instrument (one of the 10 canonical)
  • target (one of the 6 canonical, or unclear)
  • direction_burden (one of the 5)
  • direction_progressivity (one of the 4)
  • attribution (one of the 4)
  • rationale (dict — at minimum {"none": true})

Additionally, when step2_type == "proposal":

  • dimension, policy_stance, commitment_strength must all be set

When step2_type == "narrative":

  • dimension, policy_stance, commitment_strength must be ABSENT (proposals-only fields)

5.6 Codebook semantic reminders worth repeating

  • Wealth/inheritance tax CUT → direction_progressivity: less_progressive (regardless of equity rhetoric in the sentence). Cutting a progressive tax is a less-progressive change.
  • Wealth/inheritance tax UP → direction_progressivity: more_progressive.
  • VAT/excise UP → direction_progressivity: less_progressive (raising a regressive tax is less progressive).
  • VAT/excise DOWN → direction_progressivity: more_progressive.
  • Narratives must NOT carry dimension, policy_stance, or commitment_strength.

5.7 Blob-fallback rule (critical for re-coding waves)

If the Stage 1 source has n_sentences == 1, load the segmented version:

  • For non-English: data/combined_local_segmented/{key}.json (preferred) or data/combined_en_segmented/{key}.json (fallback)
  • For English-language manifestos: data/combined_local_segmented/{key}.json if it exists, else fall back to data/combined_en_segmented/{key}.json (4 English blobs lack a local-segmented file but have an en-segmented one)

When operating in blob-fallback mode:

  • SCAN EVERY SEGMENTED SENTENCE, not just the first 50. Many manifestos bury tax content past section 5.
  • Do not return zero entries unless you have read every segmented sentence. The original v2.8 cascade returned zero on 81 manifestos that clearly contained tax sentences past the early-document non-tax preamble.
  • Ignore the tax_indices: [0] from Stage 1 — for blobs it is meaningless.

5.8 Per-entry self-check before emitting

For every entry in the output, verify:

  1. All keys come from the canonical list in 5.1.
  2. All enum values come from the canonical lists in 5.2.
  3. sentence_index is an integer in [0, n_sentences).
  4. step2_type is proposal or narrative (or drop/skip for filter trail).
  5. If step2_type == "proposal": dimension, policy_stance, commitment_strength are all set.
  6. If step2_type == "narrative": dimension, policy_stance, commitment_strength are absent.
  7. rationale is a dict; every rationale_evidence key matches a true key in rationale.
  8. quantified is a bool; any specifics live in quantified_detail.
  9. target_*_tags are dicts; omitted entirely if no tag would be true.
  10. continuation is true only on non-lead fragments; lead_sentence_index points back to the lead (== same sentence_index only when multi-instrument split on the one sentence).
